# 《四季田园》第二阶段方案请求文档

> 本文档用于发给 ChatGPT 生成游戏第二阶段的设计方案。
> 分工：ChatGPT 出方案 → 工程负责人按方案定模块接口 → DeepSeek 写实现代码 → 工程负责人集成 + 测试 + 验收。

## 一、项目概况

- 产品：《四季田园》(Four Seasons Farm)，原创 2D 浏览器农场模拟经营游戏
- 风格：精致现代像素风，桌面浏览器（Chrome/Edge），单人游玩
- 技术栈：Phaser 3 (3.90.0) + TypeScript + Vite + Vitest + localStorage 存档
- 禁止：后端服务、账号系统、多人联机
- 参考玩法类型：传统农场模拟 RPG，但角色/美术/地图/剧情/文案/数据全部原创

## 二、第一阶段已完成（当前代码状态）

工程位置：`four-seasons-farm/`，已验证可运行（26 个单测全绿 + 生产构建通过 + 浏览器实机确认）。

已实现：
1. Vite + TS + Phaser 3 工程，Boot → Title → Farm 三场景
2. 原创 36×24 字符地图「青禾农庄」（草地/耕地/床/树木/岩石/篱笆/池塘）
3. 角色 WASD + 方向键移动、走/站动画帧、障碍碰撞、摄像机跟随 + 边界限制
4. HUD（季节·日期·金币·操作提示），数值变化才刷新
5. 床旁按 E 睡觉 → 日期+1 天 + 自动存档；T 回标题
6. 存档系统：localStorage，损坏数据容错
7. 领域层与场景层分离：
   - `domain/services/TimeService`（季节循环：14 天/季，春→夏→秋→冬）、`EconomyService`（金币单一事实源）
   - `game/systems/GameSession`：模块级单例，场景切换不重置游戏状态
   - 占位素材均为程序化像素图（已标记，非正式美术）

目录结构：
```
src/game/scenes|entities|systems   Phaser 层（表现）
src/domain/models|services         规则层（纯逻辑，可单测）
src/data/maps/farm01.ts            地图数据（字符网格 + 解析器）
src/persistence/save.ts           存档（可注入存储后端）
src/ui/                            预留 UI 接口
tests/                             5 组 Vitest（time/economy/save/farm01/session）
```

## 三、架构红线（方案必须遵守）

1. 游戏规则写在 domain 层，不允许只写在 UI 事件回调里
2. 金币/日期/作物等状态必须有唯一的数据模型（单一事实源），不允许场景各自持有
3. 场景切换不重置游戏状态
4. 不引入不必要的依赖；不使用 any 掩盖类型错误
5. 每个功能模块必须有可单元测试的纯逻辑部分

## 四、需要 ChatGPT 出的方案（第二阶段）

请按以下结构输出，便于直接拆解给代码实现：

### 1. 玩法设计
- 种植核心循环：选种子 → 锄地/播种 → 浇水 → 生长（分阶段）→ 收获 → 卖出/入包，交互按键与范围规则
- 种子/作物清单（原创命名），含：适种季节、生长期（天数）、收获数量、售价、售价随季节/稀有度的变化规则
- 浇水规则：一天一次？影响生长速度还是必须条件？
- 初始资金与首个经济闭环（从 0 金币到能买第二种作物）的数值曲线

### 2. 扩展功能（选做，按优先级排）
- 商店（买种子/工具）、背包（容量与分类）、季节事件/天气、动物或 NPC 任务
- 每个功能给出：核心规则、数据模型字段、与已有模块的接入点

### 3. 数据设计
- 作物/物品/价格的 TypeScript 类型定义草案
- 存档 v2 字段扩展与版本迁移规则

### 4. 数值表
- 完整数值表（Markdown 表格）：作物 × 季节 × 价格 × 生长期 × 产出
- 一天能赚多少钱的节奏目标（前 7 天 / 14 天 / 30 天）

### 5. 验收标准
- 每条功能的可测试行为描述（用于写 Vitest 用例）
- 操作说明（给玩家看的按键清单）
